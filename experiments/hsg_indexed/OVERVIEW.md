# 이번 단계의 결론

**국소 변화가 있는 큰 합성 장면에서, 계층 요약을 사용하는 HSG 부분 갱신의 B 계산 비용 이점을 확인했다.**
기존 회수 성공률의 향상과 구분해야 한다. 네 방법은 같은 탐색·방해물 제거·배치 규칙을 사용한다.

## 최종 계산 결과

호출 순서와 GC를 통제한 v2, 새 seed 12개, 총 **11,520회 B 호출**을 수행했다.
동일 프레임의 네 방식 출력은 모두 일치했다. 전체 입력 비교·관계 갱신·영역 요약 유지·조회 시간을 포함한다.
초기 캐시 구축은 별도 집계하며, 아래는 구축 이후 **국소 변화 + 목표 미식별 탐색** 조건이다.

| 관측 객체 | Flat 부분 갱신 대비 HSG 부분 갱신 속도비 | seed bootstrap 95% 구간 | 해석 |
|---:|---:|---:|---|
| 27 | 1.01배 | 0.99–1.02 | 추가 이점 불확실 |
| 216 | 1.09배 | 1.07–1.11 | 해당 조건에서 B 시간 약 8.2% 절감 |
| 1,728 | 1.15배 | 1.13–1.18 | 해당 조건에서 B 시간 약 12.7% 절감 |

속도비는 seed별 중앙 실행 시간의 비율을 다시 중앙값으로 요약했다. 시간 절감은 `1 - 1/속도비`다.
이는 이 컴퓨터와 고정 workload에 대한 기술 통계이며, 모든 환경에서의 보장이나 다중 비교를 보정한 유의성 주장이 아니다.

1,728 객체에서 전체 frame을 모은 B 시간 중앙값은 Flat 전체 재계산 23.173ms, Flat 부분 갱신 2.070ms,
HSG 전체 재계산 23.288ms, HSG 부분 갱신 1.780ms였다.
큰 폭의 차이는 부분 갱신의 공통 효과다. **이 전체 차이를 HSG 계층만의 기여로 설명하면 안 된다.**
HSG 추가 기여는 이미 공간 인덱스·부분 갱신을 갖춘 Flat과의 비교로 판단한다.

## 이점이 생긴 원인

1,728 객체의 국소 변화·목표 미식별 조건에서 상세 물체 후보 조회 수 중앙값은 Flat 1,153개, HSG 1개였다.
HSG는 대신 192개 영역 요약을 비교한다. 변경된 영역의 요약을 갱신할 때는 두 부분 갱신 방법 모두 중앙값 9개 객체를 확인했다.
입력 변경 감지를 위해 1,728개 객체를 읽는 비용은 여전히 남고 위 시간에 포함되어 있다.

전체 영역이 움직이거나 목표가 이미 식별된 조건에서는 HSG의 추가 이점이 일관되게 나타나지 않았다.
해당 결과도 [최종 표](controlled/RESULTS.md)와 [그래프](controlled/results.png)에 모두 유지했다.
지역 요약 캐시를 Flat에 추가하면 유사한 최적화를 구현할 수 있으므로, 그래프 자료구조 자체의 본질적 우월성을 주장하지 않는다.

## 물리 실행과 검증

- 새로운 RGB-D 장면 8개 × 4방법 = **32회 MuJoCo 실행**. 각 방법은 4/8 회수 성공했다.
- 같은 장면에서 네 방법의 expert 제어 명령은 바이트 단위로 동일했다. 성공률 상승을 목표로 정책을 바꾼 실험이 아니다.
- 기존 실제 RGB-D B 입력 433개에 대한 회귀 검사에서도 네 방식 모두 기존 planner와 일치했다. 이전 평가 seed를 새 성능 표본으로 재사용하지 않았다.
- 새 모듈을 연결한 RGB-D inspector 시연(seed 42)은 4개 Subgoal을 완료했다.
- 전체 unittest 109개 실행: 108개 통과, GUI 자동 테스트 1개 생략.

메모리와 초기 비용도 숨기지 않았다. 1,728 객체의 추가 Python allocation은 Flat 부분 갱신 약 2,404KB,
HSG 부분 갱신 약 2,417KB였다(입력 그래프/native 메모리 제외). 초기 구축은 각각 약 23.8ms와 24.2ms였다.
정확한 정의와 모든 크기의 수치는 최종 보고서와 압축 원자료에 있다.

## 논문에 사용할 수 있는 주장 범위

> 합성 부분 관측 장면 그래프의 국소 갱신 조건에서, 영역별 요약을 유지하는 HSG 플래너는
> 동일한 계획 결과를 유지하면서 평면 그래프 부분 갱신 구현보다 계획 계산 시간을 줄였다.
> 이 효과는 장면 규모와 질의 유형에 의존했다.

실제 RGB-D 인식부터 로봇 완료까지의 시간 단축, 실제 로봇 성공률 향상, 조작 횟수 감소를 입증한 결과는 아니다.
현재 27개 물체 환경만으로는 계층의 추가 성능 이점을 주장하기 어렵다.

v1 측정에서 호출 순서와 무변화 frame이 결합되는 문제를 확인하여, 알고리즘을 바꾸지 않고
별도 새 seed의 v2 프로토콜을 실행 전에 고정했다. 개발/v1 결과도 그대로 보존했다.
v2는 순환 GC를 B 호출 중에만 끄고 참조 카운트 비용은 유지한 microbenchmark다.
